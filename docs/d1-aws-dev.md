# MW-D1: Mock Workday on AWS (dev)

**Status:** approved for implementation up to `terraform plan`. **No `terraform apply` until the user approves the plan output.** Prod is out of scope; it reuses these modules later.

## Goal

Run Mock Workday in the AWS dev account as a disposable stack. One command creates it, a smoke test verifies it, and one command destroys it, leaving nothing billable behind. State and cheap foundations persist.

## Environment

- **AWS account:** dev project/account `729608197929`.
- **Region:** `us-east-2`. All Regional resources are created there.
- **CLI profile:** `agent-runtime`. Scripts honor `AWS_PROFILE`, defaulting to `agent-runtime`.
- **Terraform:** 1.10 or later (S3-native state locking). Use the current AWS provider major version.
- **Tags:** every resource gets default tags `Project`, `Environment=dev`, `Stack`, and `ManagedBy=terraform`.

## Ownership and layout

The network belongs to the platform foundation, not to Mock Workday. Mock Workday deploys into it like another team's service and reads network IDs through a published contract.

| Stack | Repository and path | Lifetime | Contents |
|---|---|---|---|
| `bootstrap` | `agent-cell-runtime/infra/platform/envs/dev/bootstrap` (local state, gitignored) | persistent | This account's S3 state bucket `beejmaxx-lab-tfstate-dev`: versioning, SSE-S3 encryption, public access blocked, `prevent_destroy`. **One state bucket per account**; prod gets its own in the prod account. |
| `foundation` | `agent-cell-runtime/infra/platform/envs/dev/foundation` | persistent (no hourly cost) | VPC, 2 public and 2 private subnets across two Availability Zones, internet gateway, route tables. **No NAT gateway.** Publishes IDs to SSM Parameter Store under `/lab/dev/network/` (`vpc_id`, `public_subnet_ids`, `private_subnet_ids`). |
| `registry` | `mock-workday/infra/envs/dev/registry` | persistent (pennies) | ECR repository `mock-workday`: scan on push, a lifecycle policy keeping the last 5 images, `force_delete` |
| `service` | `mock-workday/infra/envs/dev/service` (built from `mock-workday/infra/modules/service`) | **disposable** | Everything billed by the hour (below) |

- Every stack except `bootstrap` uses the S3 backend with `use_lockfile = true`. Dev bucket: `beejmaxx-lab-tfstate-dev`, region `us-east-2`. Mock Workday keys: `dev/mock-workday-registry.tfstate` and `dev/mock-workday-service.tfstate`. Pin AWS provider `~> 6.0`. Before the bucket exists, use `terraform init -backend=false` for validation.
- Mock Workday's stacks read the network only from SSM parameters, never from the foundation's Terraform state.
- `modules/service` is environment-neutral: dev-only behavior (test admin, ECS Exec) is controlled by variables that default to off. Image tag or digest, `allowed_cidr`, sizing, and log retention are variables. Prod later reuses the module with its own small composition.
- Prod will run the exact image digest verified in dev (build once, promote by digest), not a rebuild.

## Service stack

| Component | Choice |
|---|---|
| Compute | ECS cluster plus an ECS Fargate service: 1 task, ARM64 (Graviton), 0.25 vCPU / 0.5 GB, image from ECR by tag |
| Database | RDS PostgreSQL 17, `db.t4g.micro`, 20 GB gp3, single Availability Zone, private subnets. Storage encrypted with the default key. `backup_retention_period = 0`, `skip_final_snapshot = true`, `deletion_protection = false`. Master password managed by RDS in Secrets Manager (`manage_master_user_password`). |
| Application credentials | Passwords for `mw_owner` and `mw_app` generated by Terraform and stored in Secrets Manager with `recovery_window_in_days = 0`. Generated passwords are stored in Terraform state; the state bucket is private and encrypted, which is acceptable for this lab. |
| Load balancer | Public Application Load Balancer, HTTP port 80, **inbound only from `var.allowed_cidr`** (the user's IP as /32). Forwards to container port 8080 only. TLS is out of scope for dev. |
| Network placement | Tasks run in public subnets with public IPs (needed to pull images and write logs without a NAT gateway). The task security group admits traffic only from the load balancer's security group. RDS sits in private subnets and admits port 5432 only from the task security group. |
| IAM | **Execution role:** pull from ECR, write logs, read exactly the three secrets. **Task role:** only the permissions ECS Exec requires (`ssmmessages:*` on `*`, the documented minimum). Nothing else. |
| Logs | CloudWatch log group with 3-day retention, destroyed with the stack |
| Test admin | `MW_TEST_ADMIN=1` in dev. The admin port (8081) is **not** attached to the load balancer; reach it with ECS Exec and `curl localhost:8081`. ECS Exec is enabled in dev only. |
| Migration | A one-off ECS task, using the same image and network, runs `python -m mock_workday.bootstrap` with the master secret. Bootstrap must be idempotent. |

## Application changes in this repository

These are the only code changes, and the local workflow must keep working unchanged:

1. **Configuration from environment variables:** `config.py` reads database host, port, name, and credentials for the owner and app roles from the environment. Defaults reproduce the current Compose values.
2. **Bootstrap works on RDS:** given admin (master) credentials, bootstrap creates `mw_owner` and `mw_app` if they are missing, sets their passwords from the environment, then installs the schema and seed as owner. It must be idempotent. Compose can keep using `docker/init.sql` or switch to the same bootstrap path; either way, `make up` behaves as today.

## Scripts and commands (`mock-workday/infra/`)

| Command | Effect |
|---|---|
| `make aws-plan` | Plan `registry` and `service` (and prompt for `allowed_cidr`, defaulting to the caller's current public IP) |
| `make aws-up` | Apply `registry`; build the ARM64 image locally; push it to ECR; apply `service`; run the migration task; wait for the service to become healthy |
| `make aws-smoke` | Smoke test against the load balancer with `Host: acme.mockworkday.local`: Alice gets a token; reads Bob (200); Bob's compensation as Alice (403); Globex worker from the Acme host (404); revoked-grant token rejected (401) |
| `make aws-down` | Destroy `service` only; then run the leftover check |
| `make aws-leftovers` | List anything billable or tagged `Project=mock-workday` that remains. Check load balancers, target groups, ECS services and tasks, RDS instances and snapshots, NAT gateways, Elastic IPs, unattached ENIs, EBS volumes, Secrets Manager secrets (including pending deletion), and log groups. Check `us-east-2`, plus CloudWatch Logs in `us-east-1`. Exit nonzero if anything billable remains. |

The README gets an "AWS dev" section: prerequisites, the commands above, approximate hourly cost, and a reminder to run `make aws-down`.

## Cost (approximate, while the service stack is up)

| Item | Approximate cost |
|---|---|
| Fargate ARM 0.25 vCPU / 0.5 GB | about $0.01/hour |
| RDS `db.t4g.micro` plus storage | about $0.02/hour |
| Load balancer plus usage | about $0.03/hour |
| Public IPv4 addresses (load balancer and task) | about $0.015/hour |
| **Total** | **about $0.07–0.08/hour** |

Destroyed, the remaining cost is about $0: S3 state, SSM parameters, ECR storage (cents per month), and the VPC, which has no hourly cost without NAT or endpoints. RDS creation takes about 5–10 minutes.

## Acceptance

1. `terraform validate` and `plan` succeed for all stacks. The plan shows no NAT gateway and no resources outside `us-east-2`. All resources are tagged.
2. *(After user approval)* `make aws-up`, then `make aws-smoke` passes.
3. Through ECS Exec, the admin clock endpoint answers on `localhost:8081`. Port 8081 is unreachable through the load balancer.
4. `make aws-down`, then `make aws-leftovers` reports nothing billable. A second `make aws-up` reproduces the same seed IDs.
5. The local test suite still passes, and `make up` still works.

## Out of scope

Prod; TLS and custom domains; CI/CD; Multi-AZ RDS; autoscaling; WAF; running the full pytest suite against AWS.

## Implementation details and local checks

- `infra/modules/service` has no dev-specific names, account IDs or regions. Inputs
  include name, account, region, repository name, image tag/digest, network IDs,
  allowed CIDR, Fargate CPU/memory, DB class/storage and log retention.
  `enable_test_admin` and `enable_exec` default false; `envs/dev/service` sets both true.
- Application variables: `MW_DB_HOST`, `MW_DB_PORT`, `MW_DB_NAME`,
  `MW_DB_OWNER_PASSWORD`, `MW_DB_APP_PASSWORD`; optional migration-only
  `MW_DB_ADMIN_USER` and `MW_DB_ADMIN_PASSWORD`. Role names remain `mw_owner` and
  `mw_app` so the schema grants remain exact. Local defaults are unchanged.
- Terraform creates the database; bootstrap provisions its roles and schema.
  The regular task starts only the app; only the separate migration task receives
  the master password. The ALB probes `/openapi.json`; the wrapper also requires
  successful migration before reporting a healthy deployment.
- ECS Exec task permission is limited to the four channel actions:
  `CreateControlChannel`, `CreateDataChannel`, `OpenControlChannel`, `OpenDataChannel`
  under `ssmmessages`, on `*`.
